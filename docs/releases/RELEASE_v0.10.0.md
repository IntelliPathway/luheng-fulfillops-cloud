# 履衡 AI · FulfillOps Cloud v0.10.0

## 本版目标

补齐支付回执从“验签但无法匹配”到“有依据地人工确认入账”的业务闭环，同时继续保证浏览器和 Agent 都不能绕过确定性账务内核。

## 已完成

- 新增租户级回执对账提案，保存候选案件快照、人工依据、证据摘要和版本号。
- 候选建议只读取当前租户且具备完整财务档案的案件；评分和依据可解释，不自动执行匹配。
- 采用 Maker–Checker 双人门禁：运营人员或管理员可提案，必须由另一名管理员独立批准或驳回。
- 自我复核、跨租户读取、陈旧版本、重复决策和默认单步匹配均失败关闭。
- 批准时在数据库锁内重新校验回执、案件、委托期和佣金规则，并原子写入回款账簿、佣金账簿、钱指标和审计证据。
- 驳回回执不进入任何钱指标；补充证据后可按新版本重新提交。
- 前端新增「回执复核」工作台、候选建议、独立复核弹窗和最近复核记录；离线演示明确标注不写服务端账簿。
- 新增 PostgreSQL 迁移 `009_payment_reconciliation.sql`。

## 验证口径

- 后端：66 项；本地 65 项通过、1 项 PostgreSQL 专项由 CI 执行。
- 前端领域/API 契约：16 项。
- Sites Worker 与构建安全：5 项。
- 发布基线共 87 项。

## 安全边界

- `POST /payments/receipts/{id}/match` 默认停用；仅部署方明确开启兼容开关且调用者为管理员时可用。
- 候选评分不是模型置信度，也不是自动入账授权。
- 提案原因与复核结论保存于对账记录，审计事件只记录其摘要，不复制可能包含业务信息的原文。
- 支付签名密钥仍只在服务端密钥后端解析，浏览器、Agent 和对账工作台均不可读取。
