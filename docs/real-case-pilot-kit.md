# v4.5 · 首个真实案例验收材料

| 材料 | 最小要求 | 保管方式 |
|---|---|---|
| 业务授权与委托 | 授权范围、委托起止日期、债权与结算规则 | 业务方保留原件，平台仅存脱敏引用与摘要 |
| 案件导入 | 既有非 PII CSV，稳定案件编号、债权金额和来源引用 | 导入者与确认者必须不同 |
| 独立复核人员 | 两个不同企业账号及租户权限 | 企业 IdP 与平台成员关系管理 |
| 支付 / 退款凭证 | 实际签名回执、外部交易引用、到账与退款金额 | 不上传支付签名密钥；与不可变账簿逐项核对 |
| 联调与恢复记录 | 已批准 Provider、测试与启用版本、告警与恢复记录 | 作为独立验收证据提交复核 |

按 [真实案例验证流程](real-case-validation.md) 执行。需要进入支付 webhook 的案件编号使用现有 `C` 加 3–12 位数字格式（如 C900001），以同时符合导入与支付契约。金额统一为整数分，退款关联原支付事件。

验收至少覆盖一次付款、一次部分退款、重复回执、错误签名、跨租户查询及保护暂停。净回款必须与外部凭证一致；重复回执不得重复记账，错误签名不得入账，保护案件不得恢复触达。记录失败恢复后同一事件的处理结果。

签字项：来源真实性、业务授权、银行/服务商凭证一致性、独立复核、异常和恢复结果。系统报告永远不替代这些外部确认。合成案例、开发登录与沙箱 Provider 不能签署为真实生产验收。

在试点中心填写同一案件全部期间的外部凭证净额，单位为整数分（如 7000 表示 70 元）。报告拆分付款与退款，并显示平台减外部的差异；空金额不比对，无有效回款链时差异不可用。金额一致也必须由独立人员核查原始银行/服务商凭证，平台不存原件、不声明真实验收通过。
