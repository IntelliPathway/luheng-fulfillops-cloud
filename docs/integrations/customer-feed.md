# 客户连接器与统一事件协议

连接器拉取已授权、脱敏的全历史案件付款/退款汇总，仅创建材料事件，不记账、验签或代替客户真实性核验。配置管理员需持有客户 Bearer 凭证；服务端复用 OIDC、租户成员权限和可解析的加密密钥存储。

| 环节 | 行为 |
|---|---|
| 保存 | 名称、HTTPS 地址、3 个不同字段映射、5–1440 分钟间隔；凭证只返回是否已配置 |
| 测试 | 向真实客户接口执行只读 GET 并验证事件协议，不创建材料；有效期 24 小时 |
| 启用 | 管理员明确操作后独立 Worker 按间隔拉取；修改配置或失败重测立即停止 |
| 同步 | 复用持久租约队列，同一连接器不并发提交；失败页必须先重试 |
| 断点 | 本页全部事件加密留存后推进游标，材料处理是后续作业；部分页失败保留原游标 |
| 重放 | 连接器 ID + 客户事件编号去重；同 ID 不同内容返回冲突，不覆盖旧材料 |

客户接口收到 `GET /events?cursor=<opaque>&limit=20`，认证头为 `Authorization: Bearer ...`。初始 cursor 为空。响应示例（合成数据）：

```json
{"events":[{"event_id":"BANK-EVENT-001","source_reference":"BANK/TEST-001","records":[{"case":"C002","pay":0,"refund":0}]}],"next_cursor":"checkpoint-1"}
```

示例映射：`case_id→case`、`payment_cents→pay`、`refund_cents→refund`。金额必须是非负整数分，不接收浮点或布尔值；每个事件 1–50 个不同案件，每页最多 20 个事件、响应最多 2 MB。非空页必须推进游标。客户应提供稳定、不会遗漏更新的游标；数据变更必须发新事件号。乱序事件作为独立声明留存，不自动覆盖案件或账簿。

部署配置 `CUSTOMER_CONNECTOR_EGRESS_ALLOWLIST` 为精确公网主机名列表，默认拒绝全部。只允许 HTTPS 443；DNS 全部地址必须公网，并按解析 IP 固定本次 TLS 连接，仍按原主机校验 TLS。拒绝重定向、URL 凭证、查询参数和私网地址，不使用环境代理。网络请求 10 秒超时。客户专有 OAuth/API 协议需在客户侧适配成此协议，不能把任何私有 API 宣称为已兼容。

自动调度依赖现有 `python -m app.worker`，部署需迁移 032。管理员权限失效、测试过期、历史密钥缺失或配置版本变化时失败关闭。24 小时后需要重测；这是有界授权，不是假定持续健康。
