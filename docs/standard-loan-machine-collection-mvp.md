## 目标与边界

在现有 v5.0 基础上完成一个可试点的纵向闭环：授权接案 → 执行前检查 → 本人核验 → 债务说明 → 记录还款承诺 → 到期核验到账 → 结案、有限重试或异常暂停。

首期为一家机构、一个个人无抵押贷款产品、一个电话 Provider、一个经批准的模型和一套机构政策。沿用多租户底座，不建设新的多机构运营产品。候选准入范围为早期逾期，例如 DPD 1–30；最终以机构发布的政策为准，这不是监管阈值。要求债权、委托、余额、联系依据和联系对象均可核验。争议、投诉、身份不明、特殊困难和司法案件不进入正常自动清收流程。

业务范围包括债务核实、原约定还款提醒、金额与日期明确的还款承诺（PTP）、失约后的受限重新决策。PTP 不改写合同，不等于签署分期方案或到账。协商减免、展期和新分期只记录请求并转交机构；现有独立审批约束保持有效。

机构管理员通过结构化流程确认活动、政策、范围、预算及允许动作；自主执行只能发生在该授权内。模型不能从全局聊天直接启动外呼、发布政策、解除保护或写账。每次执行前重新检查当前授权及案件状态。

## 三轮交付

以下为依赖可用时的工程估算，不是固定交付承诺；先完成可独立验收的软件工作，外部接入缺口进入备忘录。

| 轮次 | 估算 | 工作 | 验收出口 |
|---|---|---|---|
| A：可接案、可阻断 | 约 2 个工程工作日 | 真实案件 ID 精确传递；贷款字段校验；不透明联系引用；租户政策；授权快照；原子频次预占；执行前门禁；统一可用性状态 | 非 C 开头案件可处理且不串租户；无依据、保护、终态、超频、过期授权被阻断；并发不会超配额 |
| B：可通话、可记录 | 约 3–4 个工程工作日 | 一个电话 Provider 接口与 Worker；一个受控模型；语音识别/合成及打断；本人核验；有限状态对话；PTP；错人/异议/投诉暂停；真实回执验签、去重及关联 | 测试号码完成真实对话；核验前不披露债务；金额来自权威查询；不确定回答停止披露；回执可追溯且重放不重复执行 |
| C：可履约、可验收 | 约 2–3 个工程工作日 | PTP 到期任务；已核验回款驱动状态；受限失约重试；精简运营页；离线对话集和故障回放；受控试点清单 | 承诺与到账分离；晚到/重复回执及部分还款正确；保护/到账后不再执行失效联系任务；软件报告与真实试点报告分别输出 |

合计约 7–9 个工程工作日。电话媒体能力、模型服务、企业 API/OIDC 和测试环境已可用是估算前提。Provider 仅提供呼叫回执而无实时媒体或受控对话能力时，B 轮须重新估算。未选择 Provider 时先交付契约、模拟器和适配测试，不能把模拟通过标记为真实接通。

## 最小数据增量

- 贷款事实：产品、到期日、逾期天数、币种、权威应还余额及构成、账务快照时间和来源。金额使用整数分；不可从历史样例补全。
- 联系引用：加密受控存储或 Provider 联系人引用、本人核验结果、渠道许可、错误号码标记。CSV 保持既有非 PII 契约，模型及普通日志不接收明文号码。
- 执行授权：机构、活动、案件范围、政策版本、授权期限、限额、暂停状态。排队后配置变化触发执行前失效检查。
- 对话会话：通话关联 ID、关键事件、核验状态、结构化意图、终止原因、必要的受控转写/录音引用及保留期限。
- PTP：案件、金额、日期与时区、明确确认的证据、当前状态、兑现核验。与正式 RepaymentPlan 分离；自述到账保留为待核实陈述。
- 运行轨迹：动作及幂等键、配额预占、执行结果、模型和政策版本、Provider 回执及支付回执关联。

## 对话与权限

对话只支持：身份核验 → 债务说明 → 原约定还款询问 → PTP 确认 → 结束。错人、已还款待核实、异议、投诉、困难或人工请求进入对应暂停/转交分支。身份核验方法必须由机构确定，不能把“对方说是本人”当作充分验证。

模型输出结构化意图、候选话语和候选行动。金额、期限、联系资格及最终动作由业务服务校验。首期不允许模型自由创造折扣、罚息、承诺或法律后果。模型失败、账务过旧、核验不确定、渠道不可用时停止相应动作；不要假装模型已成功。

联系执行采用业务幂等键、Provider 幂等能力和未知结果对账。提交超时但可能已拨号时先查询 Provider，不盲目重拨。全局停机开关、单租户暂停和单案件保护均在执行边界生效。

## 验收与试点

1. 软件验收：至少覆盖本人核验、错人、拒绝核验、债务异议、投诉、困难、PTP、失约、部分到账、已结清、过期委托、超频、重复/乱序回执、Worker 重启与 Provider 超时等场景；租户隔离、金额一致性、禁止动作和重复执行测试不得失败。
2. 内部联调：获准测试号码完成真实媒体链路；真实到账链路由机构支持的测试环境验证。模拟、测试环境和生产证据明确分开。
3. 真实试点：建议从 20–50 个合格案件开始，在机构完成授权后执行。该样本用于验证闭环与运营问题，不用于宣称显著回款提升；扩大后再设置同期对照评估增量效果。
4. 指标：符合准入案件的自动完成率、异常率、PTP 兑现率、已确认回款、单案成本、错人联系和越权/超频事件。后两类事件出现即暂停受影响执行并调查。

## 暂缓与依赖备忘录

暂缓：多个 Harness 替换评测、多渠道、复杂分期与减免、自动策略实验、通用知识图谱、司法处置、大规模 BI、平台重构和 UI 重做。既有财务兼容能力保留，不扩展退款业务。

外部依赖：电话 Provider 的 API、实时媒体/对话能力、回执验证与幂等接口；机构批准的模型和语音服务；联系对象安全解析；本人核验方式；权威账务/支付回执；企业 API/OIDC 的实际部署；机构发布的政策、授权和异常接收渠道。开发期间记录缺口并继续独立工作；真实客户联系须依赖上述条件，不以测试替代授权。

## SIP / Linphone 内部联调与派发契约（2026-10-07）

本轮新增 `backend/app/loan_telephony.py`：不可变派发请求、Provider 接口和回执状态裁决，17 项专项测试。仅为适配器前置契约，尚未接入 API、持久队列或网络，不宣称电话 Provider 已实现。现有 provider 模式继续返回 503。

内部测试采用“机催 Worker → 电话适配器 → 自有 SIP/PBX 与媒体桥 → Linphone 测试分机”。Linphone 是接听端；媒体桥接 ASR、受控模型和 TTS 后才能验收 AI 双向对话。SIP 分机通话不证明普通手机号可拨通；后者需要运营商线路。使用自有 SIP 测试账号和合成案件，不将公共免费 SIP 服务视为机构生产线路。官方参考：https://www.linphone.org/en/faq/ 、https://www.linphone.org/en/getting-started/ 。

派发请求仅含租户、会话、幂等键、不透明联系引用和政策/资料版本，不传裸号码或债务信息。未来适配器须在发送前重新核验授权、政策、保护、配额与测试端点白名单；当前契约不具备这些执行门禁。

状态规则：prepared → dispatching → accepted/ringing/answered → ended/failed；请求超时进入 unknown。只有 prepared 可以首次派发；unknown 必须按原幂等键查询，查询无结果也不能盲目重拨。回执核对租户、派发键与 Provider call ID，旧序号忽略，状态不倒退，终态冲突进入人工核查。响铃/接听不等于本人核验，不触发债务披露或还款承诺。

后续实现必须先持久化派发状态，再调用 Provider；使用原子状态迁移、回执原文验签、序号与摘要去重、租约恢复和未知结果对账。当前纯函数没有替代这些保证。

联调验收顺序：
1. 同一 SIP 服务下测试分机互拨，确认注册、双向音频和挂断。
2. 后端只呼叫白名单测试分机，确认派发键与 call ID 关联；拒接/忙线/未接正确结束。
3. 模拟派发超时、Worker 重启和乱序重复回执，确认不重复拨号。
4. 接入媒体与机构本人核验；核验前不披露债务，错人/异议/投诉停止对话。
5. 验收真实承诺与到账闭环；分开记录契约测试、真实 SIP 媒体、模型和机构核验结果。

### Worker 派发门禁检查（2026-10-07）

### 固定分机持久派发（2026-10-07）

新增 LoanSipDispatch 和迁移 037；使用现有 loan.sip_echo Worker，发送前持久化 dispatching 意图。仅 development/test、显式 ENABLE_SIP_LAB 与 SIP_LAB_TENANT_ID 精确绑定的租户可用；本机网关与固定 PJSIP/1001、回声拨号计划不接受覆盖。API 和 Worker 必须运行在暴露 ARI 的同一主机网络上下文；普通容器的 127.0.0.1 不指向宿主机。凭据只从进程环境读取。该路径不承载客户联系、本人核验或债务说明。

| API（前缀 /api/v1/loan-collection） | 行为 |
|---|---|
| POST /sessions/{id}/sip-echo | 管理员确认 test_extension_only=true、acknowledged=true 及 expected_version；原子预留、排队，202 |
| GET /sip-dispatches/{id} | 当前租户持久记录和有限网关观察 |
| POST /sip-dispatches/{id}/reconcile | 管理员确认及 request_key；只查询同呼叫 ID，202 |
| POST /sip-dispatches/{id}/stop | 管理员确认及 request_key；未发送立即阻断，已发送排队请求挂断，202 |

同租户同会话最多一条派发，换请求键不允许重拨；实例变更阻断原任务。租户北京时间日上限 20 次，同案上限采用当前政策（1–3）。预留、未知和阻断结果均占额度，不因失败、停止或政策变更释放；这是内部测试配额，不是跨渠道生产配额。

Worker 先核验最新授权/保护/余额/会话与资料政策版本，持久意图提交后再次锁定作用域复核权限、任务租约和取消状态，才发送固定测试呼叫。提交超时、租约恢复或进程崩溃后的原派发只 GET 查询，404 不证明未发送或正常结束。submitted 只表示网关确认创建；Up 不证明双向音频或真实身份，audio_verified/ai_dialogue_ready/pstn_enabled 始终 false。

政策变更、资料更新或会话进入暂停/结束/承诺/自述付款状态会阻断 prepared，并原子排队停止已发送回声测试；挂断回执仍不等于完成核验。现有真实案件保护不因沙箱事件自动改变。SIP 回声最长 60 秒，停止动作由 Worker 处理；没有 Worker 不保证及时挂断。

本轮后端完整回归 356 项通过、2 项 PostgreSQL 专项跳过。新增 17 项派发测试及机催相关专项 65 项通过。真实 Docker/SIP 注册、响铃、RTP、PostgreSQL 迁移 037 与客户业务部署仍未验收。

### 停止请求与派发并发

停止 API 及政策、资料、会话变化触发的停止任务，会在同一事务立即持久化 `stop_requested`（未发起的 `prepared` 仍变为 `blocked`）。Worker 在派发意图提交后、重新取得租户与案件锁时刷新派发记录；若状态已变化，禁止原始 POST。已经开始的请求按锁顺序完成，再由停止任务 DELETE 原固定通道。查询保留停止回执，不恢复派发资格，也不将 404 当成音频验收证据。

本轮验证：SIP 派发、标准贷款会话、租户政策及派发门禁四组回归 67 项通过，Ruff 通过。此轮未重跑全库测试，未执行真实 Asterisk/RTP 或 PostgreSQL 并发验收，无新增数据库迁移。
