# 标准个人贷款机催 MVP 执行计划

更新日期：2026-10-07。状态：首轮软件增量已实现；后续真实渠道与试点待接入，不代表真实外呼已获授权。

## 目标与边界

在现有 v5.0 基础上完成一个可试点的纵向闭环：授权接案 → 执行前检查 → 本人核验 → 债务说明 → 记录还款承诺 → 到期核验到账 → 结案、有限重试或异常暂停。

首期为一家机构、一个个人无抵押贷款产品、一个电话 Provider、一个经批准的模型和一套机构政策。沿用多租户底座，不建设新的多机构运营产品。候选准入范围为早期逾期，例如 DPD 1–30；最终以机构发布的政策为准，这不是监管阈值。要求债权、委托、余额、联系依据和联系对象均可核验。争议、投诉、身份不明、特殊困难和司法案件不进入正常自动清收流程。

业务范围包括债务核实、原约定还款提醒、金额与日期明确的还款承诺（PTP）、失约后的受限重新决策。PTP 不改写合同，不等于签署分期方案或到账。协商减免、展期和新分期只记录请求并转交机构；现有独立审批约束保持有效。

机构管理员通过结构化流程确认活动、政策、范围、预算及允许动作；自主执行只能发生在该授权内。模型不能从全局聊天直接启动外呼、发布政策、解除保护或写账。每次执行前重新检查当前授权及案件状态。

## 三轮交付

以下为依赖可用时的工程估算，不是固定交付承诺；先完成可独立验收的软件工作，外部接入缺口进入备忘录。

| 轮次 | 估算 | 工作 | 验收出口 |
|---|---|---|---|
| A：可接案、可阻断 | 约 2 个工程工作日 | 真实案件 ID 精确传递；贷款字段校验；不透明联系引用；租户政策；授权快照；原子频次预占；执行前门禁；统一可用性状态 | 非 C 开头案件可处理且不串租户；无依据、保护、终态、超频、过期授权被阻断；并发不会超配额 |
| B：可通话、可记录 | 约 3–4 个工程工作日 | 一个电话 Provider 接口与 Worker；一个受控模型；语音识别/合成及打断；本人核验；有限状态对话；PTP；错人/异议/投诉暂停；真实回执验签、去重及关联 | 测试号码完成真实对话；核验前不披露债务；金额来自权威查询；不确定回答停止披露；回执可追溯且重放不重复执行 |
| C：可履约、可验收 | 约 2–3 个工程工作日 | PTP 到期任务；已核验回款驱动状态；受限失约重试；精简运营页；离线对话集和故障回放；受控试点清单 | 承诺与到账分离；晚到/重复回执及部分还款正确；保护/到账后不再执行失效联系任务；软件报告与真实试点报告分别输出 |

合计约 7–9 个工程工作日。电话媒体能力、模型服务、企业 API/OIDC 和测试环境已可用是估算前提。Provider 仅提供呼叫回执而无实时媒体或受控对话能力时，B 轮须重新估算。未选择 Provider 时先交付契约、模拟器和适配测试，不能把模拟通过标记为真实接通。

## 最小数据增量

- 贷款事实：产品、到期日、逾期天数、币种、权威应还余额及构成、账务快照时间和来源。金额使用整数分；不可从历史样例补全。
- 联系引用：加密受控存储或 Provider 联系人引用、本人核验结果、渠道许可、错误号码标记。CSV 保持既有非 PII 契约，模型及普通日志不接收明文号码。
- 执行授权：机构、活动、案件范围、政策版本、授权期限、限额、暂停状态。排队后配置变化触发执行前失效检查。
- 对话会话：通话关联 ID、关键事件、核验状态、结构化意图、终止原因、必要的受控转写/录音引用及保留期限。
- PTP：案件、金额、日期与时区、明确确认的证据、当前状态、兑现核验。与正式 RepaymentPlan 分离；自述到账保留为待核实陈述。
- 运行轨迹：动作及幂等键、配额预占、执行结果、模型和政策版本、Provider 回执及支付回执关联。

## 对话与权限

对话只支持：身份核验 → 债务说明 → 原约定还款询问 → PTP 确认 → 结束。错人、已还款待核实、异议、投诉、困难或人工请求进入对应暂停/转交分支。身份核验方法必须由机构确定，不能把“对方说是本人”当作充分验证。

模型输出结构化意图、候选话语和候选行动。金额、期限、联系资格及最终动作由业务服务校验。首期不允许模型自由创造折扣、罚息、承诺或法律后果。模型失败、账务过旧、核验不确定、渠道不可用时停止相应动作；不要假装模型已成功。

联系执行采用业务幂等键、Provider 幂等能力和未知结果对账。提交超时但可能已拨号时先查询 Provider，不盲目重拨。全局停机开关、单租户暂停和单案件保护均在执行边界生效。

## 验收与试点

1. 软件验收：至少覆盖本人核验、错人、拒绝核验、债务异议、投诉、困难、PTP、失约、部分到账、已结清、过期委托、超频、重复/乱序回执、Worker 重启与 Provider 超时等场景；租户隔离、金额一致性、禁止动作和重复执行测试不得失败。
2. 内部联调：获准测试号码完成真实媒体链路；真实到账链路由机构支持的测试环境验证。模拟、测试环境和生产证据明确分开。
3. 真实试点：建议从 20–50 个合格案件开始，在机构完成授权后执行。该样本用于验证闭环与运营问题，不用于宣称显著回款提升；扩大后再设置同期对照评估增量效果。
4. 指标：符合准入案件的自动完成率、异常率、PTP 兑现率、已确认回款、单案成本、错人联系和越权/超频事件。后两类事件出现即暂停受影响执行并调查。

## 暂缓与依赖备忘录

暂缓：多个 Harness 替换评测、多渠道、复杂分期与减免、自动策略实验、通用知识图谱、司法处置、大规模 BI、平台重构和 UI 重做。既有财务兼容能力保留，不扩展退款业务。

外部依赖：电话 Provider 的 API、实时媒体/对话能力、回执验证与幂等接口；机构批准的模型和语音服务；联系对象安全解析；本人核验方式；权威账务/支付回执；企业 API/OIDC 的实际部署；机构发布的政策、授权和异常接收渠道。开发期间记录缺口并继续独立工作；真实客户联系须依赖上述条件，不以测试替代授权。

## 文档与发布纪律

每轮交付更新功能规格、架构、配置/运维及相关测试证据；仅变化涉及的文档更新。采用一个稳定 MVP 计划和既有 CHANGELOG/RELEASE，不再新增每小轮发布说明。当前文件记录计划；实现后应将逐项状态改为已实现、已测试、已接通或待外部验收。当前 v5.0 既有版本号不因计划创建而改变。

## 本轮实现与剩余工作（2026-10-07）

已实现：标准贷款资料/准入、真实案件 ID 受控读取、管理员授权沙箱会话、模拟本人核验及事件状态机、PTP、事件幂等/版本检查、资料变化与保护复核、到期 Worker 核验、在线机催入口、迁移 034。现有联系频次使用案件写锁串行计数，电话回执不覆盖保护/终态、不倒退阶段。

目前未调用真实电话或模型。沙箱模拟异常不影响真实案件；资料快照是管理员陈述。PTP 核验依据现有净回款账本与记录时基线，表示之后的净回款变化，不是合同级支付归因，不能作为因果效果指标。退款可能使兑现状态重新变化。资料更新后旧承诺核验需核实，不自动改基线。

剩余：机构版本化联系时段与活动授权快照；真实 Provider 派发/媒体、身份核验及结构化对话；真实异常保护关联；权威源账务时间映射；生产联调与小样本试点。沙箱日限额与真实联系计数相互独立，不能代替真实渠道频次控制。

### 联调 API

- `GET /api/v1/loan-collection/overview`：租户会话与真实可用性。
- `GET /cases/{case_id}/profile`、`PUT /cases/{case_id}/profile`：资料快照；PUT 需管理员、确认与 expected_version。
- `GET /cases/{case_id}/preflight`：准入及依赖阻断。
- `POST /sessions`：管理员确认创建沙箱会话，request_key 幂等；真实模式不降级。
- `POST /sessions/{id}/events`：结构化模拟事件，event_key、expected_version 与确认必需。
- `POST /sessions/{id}/reconcile`：读取账本核验 PTP；不会改变账务。

以上相对路径均以 `/api/v1/loan-collection` 为前缀。界面入口为“标准贷款机催”；未连接 API 时只显示接入引导，不生成离线成功。
