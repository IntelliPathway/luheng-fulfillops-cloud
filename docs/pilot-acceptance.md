# 生产试点验收

v4.1 交付证据治理，不替代真实环境验收。在线「试点验收」页或 `/api/v1/pilot` API 是入口。

| 验收项 | 外部验收记录必须证明 |
|---|---|
| 企业身份与成员映射 | 真实 IdP 登录、租户映射、角色限制、停用账号访问拒绝 |
| 联系与录音批准 | 联系时间与频次、停止联系、录音规则、人工接管经过业务负责人核验 |
| Provider | 已选模型/通信/支付的真实沙箱联调，异常回执、幂等、人工接管；未使用渠道明确注明不在范围内 |
| 备份恢复与告警 | 在隔离恢复库还原备份，核验案件、账簿与审计；记录 RPO/RTO、Worker 恢复、告警送达 |

## 提交与复核

1. 将脱敏验收报告保存到企业受控证据系统，计算报告的 SHA-256。
2. operator/admin 提交记录编号、摘要和 1–90 天有效期；不提交原文、密钥、账号密码或个人信息。
3. 另一名 admin 独立打开外部报告，核验摘要、结果和范围，再批准或驳回。系统存储的是声明及审计轨迹，不会自动读取报告。
4. 自动安全检查通过、业务无阻断、四项最新证据批准且有效，联合门禁才显示 `accepted`。

新提交会覆盖该项目的有效判定，旧记录保留。待复核、驳回、过期、配置失效都不能通过人工验收。

## 变更与部署

- 先应用 `027_pilot_evidence.sql`（启动迁移会自动执行），再部署 API 与前端。
- 每次应用、数据库目标、凭据轮换或基础设施调整，部署环境必须更新非敏感 `PILOT_DEPLOYMENT_REVISION`（推荐 release SHA + 部署序号）。这会使现有批准失效。凭据值从不进入指纹。
- 成员角色/状态、租户生命周期、服务/渠道/支付/Harness 版本或状态变化自动使记录失效。
- `JOB_EXECUTION_MODE=external` 只证明配置，不能证明 Worker 存活；恢复与监控仍由外部记录核验。
- 门禁状态不改变套餐、渠道或 Provider 的执行权限，也不证明生产业务已实际运行。

## 首租户闭环验收

在受控试点中验证「脱敏 CSV 预演 → 独立导入 → 策略提案与独立批准 → 联系任务与人工接管 → 验签回执/对账 → 履约期次 → 佣金与审计」。每一步记录业务对象 ID、操作者与复核人、账簿摘要、异常处理结果。禁止以演示数据或契约测试代替真实试点记录。

恢复演练必须在隔离环境进行，不向生产库覆盖恢复；演练通过后再将对应报告提交到验收页。
